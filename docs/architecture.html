Architecture proposal · before implementation

The Adaptive Engine

Turning Symbol Span from a one-shot question generator into a system with memory — one that knows what she knows, what has decayed, and what is worth her next twenty minutes.

Since this was written — the app shipped and was renamed Learnometry. It now supports more than one student, each with their own profile from either a neuropsychological report or an in-app screener, so the single hard-coded profile described below is one seeded user rather than a global constant. Everything else here was built as proposed. This page is kept as the record of the design decision, not as current documentation — the README is that.

Repo symbol-span · 2,795 lines · no VCS yet Student SGU Term 4 Reference First Aid 2023, 849pp

01Current architecture

The existing app is a good generator and a nonexistent system of record. Everything you asked for lives on the second half.

The three blockers

Concept identity is session-scoped. concept_id is "c1", "c2" — generated fresh per analyze() call and meaningless across sessions. Mastery tracking is impossible until concepts have stable global identity. This is the root blocker and it moves to Phase 1.

No attempt history. Sessions save as opaque JSON blobs; nothing is queryable. Your requirement 19 — "do not throw historical attempts away" — is the single hardest thing to retrofit, so it goes in first.

The textbook doesn't fit. First Aid is 849 pages / 257 MB, over the 100 MB upload cap and far past what one request can hold. It needs section-level chunked ingestion, which is a different pipeline from the existing lecture-file route.

The PDF has a clean text layer (~2.6k chars/page, no scanned images) and every page carries a running header with its section breadcrumb — Pharmacology ` PHARMACOLOGY—AUTONOMIC DRUGS. That header is the taxonomy hook, and it means ingestion runs locally without sending the book anywhere.

02What we reuse

No parallel systems. Four existing pieces already do what the spec asks for under different names.

Reuse

Three-way scoring already is your confidence input. The app scores knew it / knew it, needed the word / didn't know it. Your §5 asks for knew it / unsure / guessed. Same axis — the existing one is inferred from cue use, yours is self-reported. Keep both signals on one confidence field and let self-report override the inference.

Reuse

The retrieval ladder is your question-format axis. recognition / cued_recall / discrimination / application / visual_map feeds §8's format analytics directly. It is orthogonal to your L1–L4 difficulty axis, not a duplicate — keep both and track them independently, exactly as §2 asks.

Extend

The concept inventory becomes the concept table. analyze() already emits name, one-liner, yield tier, and confusable_with. That last field is a ready-made edge for the §18 concept graph. Add slug identity and persist.

Extend

md(), the quiz core, and the mastery palette carry over. The renderer, option grading, fuzzy answer matching, and the CSS token system all survive. The heatmap ramp extends the existing --good/--bad tokens rather than introducing a second color language.

New

Genuinely new: persistence, scheduling, mastery math, selection, the concept graph, book ingestion, Anki export, progression, analytics. These have no existing counterpart to reuse.

!One conflict to settle first

Three items in the game spec contradict the neuropsych report this codebase is built on. All three are fixable without losing the mechanic.

Response time must not feed mastery

§4 lists averageResponseTime as a mastery variable and §19 stores responseTime. Her Color Naming is at the 5th percentile — measurably slow lexical retrieval, plausibly compounded by ESL. Feeding response time into mastery would systematically score her down for the exact deficit the report says never to penalize, and it would do so invisibly.

Resolution: store it, never let it touch the mastery formula. Use it only as a within-concept trend against her own baseline ("this concept is getting faster for you"), never as an absolute or cross-concept comparison.

Momentum yes, time pressure no

"Next question appears almost instantly" and "reduce opportunities to leave" are good design and I'll build them. But extended time is a formal accommodation, and countdown timers, speed bonuses, or a decaying streak clock would each convert a support into a stressor. The report also notes this working-memory pattern is produced by anxiety — a system that generates anxiety degrades the very thing it measures.

Resolution: fast transitions, never a timed answer. Streaks count correct answers, not consecutive days, and never reset punitively for a break. Progress bars fill; nothing drains.

Boss questions cap at three concepts

§12 wants boss questions combining several concepts from a system. Multi-concept integration at L4 is exactly right for her intact fluid reasoning (FRI 101) — but the premises must live in an on-screen table, not in her head. Digits Forward = 6 means a four-premise stem tests registration, not medicine.

Resolution: boss questions get L4 difficulty and multi-system content, hard-capped at 3 held elements, with every premise rendered in a visible table.

Two decisions worth calling out. Mastery is a cache, not a source of truth — it is always recomputable from attempt, so a formula change is a backfill rather than a migration. 04Adaptive engine

Two layers: a per-concept mastery model, and a per-question selector that treats your seven priorities as a composition target rather than a sort order.

Color bands

Bands read from effectiveMastery, which folds decay in so a stale concept drifts back down the ramp rather than flipping instantly.

Red · weakAppears most often. Drives the priority queue.< 0.35
Orange · developingFrequent, difficulty ratcheting upward.0.35 – 0.50
Yellow · inconsistentBand or high variance in recent credit.0.50 – 0.65
Light green · strongSpaced review only.0.65 – 0.85
Dark green · masteredRequires retention > 0.70 as well.≥ 0.85

Yellow is the one band that isn't purely a threshold. If the standard deviation of recent correctness reaches 0.45 — genuinely mixed, not merely mid-range — the concept reads yellow regardless of its mean. The override deliberately does not apply below orange: alternating right and wrong at 50% is weak, not inconsistent, and calling that yellow would understate it.

Variant rotation

The Keybr property you asked for: hammer the weakness, never the item. A concept carries questions tagged by format × difficulty. When a weak concept is selected, the engine picks the cell she has seen least recently, so CN III palsy returns as anatomy, then lesion localization, then pupillary findings, then a vignette — never the same stem twice in a row.

05Mastery formula

Not percent correct. Recency-weighted credit, scaled by difficulty and self-reported confidence, shrunk toward a prior when the sample is thin.

# per attempt, in [0,1] for correct; negative pull for incorrect difficultyWeight = {L1:0.60, L2:0.85, L3:1.00, L4:1.15} confidenceCredit correct : knew 1.00 · unsure 0.75 · guessed 0.45 incorrect: confident 1.60 · unsure 1.00 · guessed 0.70 (penalty multiplier) credit_i = correct ? difficultyWeight · confidenceCredit : -0.5 · difficultyWeight · confidenceCredit # Two questions, two denominators - keeping them separate matters. # 1. WHAT IS THE MEAN? recency-weighted, newest attempt weight 1 w_i = 0.85 ^ rank_i mean = Σ credit_i·w_i / Σ w_i # 2. HOW MUCH DO WE TRUST IT? shrink by attempt COUNT, not by Σw mastery = clamp01( (mean·n + α·0.35) / (n + α) ), n = min(attempts, 20), α = 3 # decay is tracked separately and never overwrites mastery stability = interval_d · ease # days; falls back to 1 + 20·mastery retention = exp( -daysSinceReview / stability ) forgettingRisk = 1 - retention effectiveMastery = mastery · (0.6 + 0.4 · retention)

Those two denominators were one denominator in the first cut, and it produced a bug worth recording: Σw saturates near 6.4, so the prior kept about 30% of the weight forever and dark green became mathematically unreachable - sustained perfect Level 3 work topped out at 0.793 against a 0.85 threshold. Raising the decay constant to compensate then broke recency, ranking a declining student above an improving one. They are different questions and need different divisors.

Four properties fall out of this. A confidently wrong answer costs about 3.5× what a hedged wrong answer costs, which is the misconception signal §5 asks for. Four attempts can't produce a green concept — the prior holds it down until there's evidence. And each practice level carries a hard mastery ceiling:

Sustained practice atMastery ceilingCan reach mastered?
Level 1, confident0.567No
Level 2, unsure0.600No
Level 3, confident0.915Yes
Level 4, confident1.000Yes

That is the point of tracking difficulty separately from mastery: you cannot master a concept by answering recall questions about it, however many you answer. The engine has to escalate, which is why pick_cell serves the hardest available variant once a concept passes 0.60.

Three separate numbers get displayed, never collapsed: mastery (how well she knows it), retention (how likely that's still true), and estimateConfidence (how sure the system is, from effective sample size). Your §21 example — "Mastery 91% / Retention confidence 62% / Review due" — is exactly this.

06Selection formula

Your §25 priority equation, made concrete — then deliberately loosened so sessions don't become identical.

priority(concept) = weakness^1.5 # 1 - effectiveMastery, superlinear · (0.5 + 1.5 · highYield) # 0.5x .. 2.0x · (0.3 + 0.7 · forgettingRisk) # never 0: green still returns · examRelevance # 1.0, or up to 2.5x inside an exam window · (1 + max(0, accL1 - accL3)) # the difficultyGap term · cooldown # 0 if seen in last 6 items this session # selection is softmax-sampled, not argmax, within each bucket P(c) ∝ exp( priority(c) / τ ), τ = 0.35

Session composition

Your seven priorities become quotas, so a session is a balanced draw rather than seven greedy picks:

BucketSharePurpose
Weak concepts35%The core loop
High-yield gaps20%Exam value per minute
Spaced repetition due20%Retention maintenance
Recently missed10%Same-session consolidation
Graph neighbors of missed5%Isolated fact or whole cluster?
Mastered spot-check5%Catches silent decay
New material5%Forward progress

Session modes reweight these quotas rather than running separate code paths — Weak Areas pushes bucket 1 to 70%, Spaced Repetition Due pushes bucket 3 to 80%, Exam Cram raises examRelevance and collapses buckets 6 and 7 to zero.

§First Aid ingestion

Local extraction, structural mapping, zero verbatim storage.

  1. Segment locally with pypdf. The running header gives every page its section path; the outline gives chapter boundaries. No upload, no API cost, no copy of the book leaving the machine.
  2. Build the topic tree from those section paths. First Aid's own hierarchy — Renal → Physiology, Renal → Pathology, Renal → Pharmacology — becomes the app's taxonomy directly. It is already the taxonomy the exam is written against.
  3. Extract concept names per section via Claude, one section at a time. What persists is the name, its topic path, its page range, and a high-yield estimate. Not the prose.
  4. Score high-yield from structural signals: presence in the Rapid Review section (pp. 730–760 — Classic Presentations, Classic Labs, Key Associations, Easily Confused Medications is a distilled high-yield index), density of coverage, cross-section recurrence, and repetition across her other uploaded materials.
  5. Generate questions from the concept name, not from the page text — Claude's own knowledge, anchored to the concept and its section, with a citation like First Aid — Renal, Pathology (p. 641).

Copyright boundary

The database stores concept names, topic paths, page references, and high-yield scores. It does not store extracted prose, tables, figures, or First Aid's mnemonics. Section text is held in memory during a single ingestion call and discarded. The user sees citations pointing into her own copy — never reproduced passages.

This is also the pedagogically correct call for her: First Aid's mnemonics are long verbal letter-strings, which the learner profile already rules out in favor of visual and spatial hooks.

07File changes

Additive. Nothing existing is deleted; app.py is the only file that gets restructured, into routers.

Two modules are deliberately pure functions over plain data — mastery.py and scheduler.py. They're where every bug that matters will live, and keeping them free of database and network calls is what makes them testable against hand-built attempt histories.

3Her own layer

Terms, exams, a vault, a pinboard, captured instructor emphasis, and time-boxed plans. Added after the original eight were drawn up.

A second axis, not a second taxonomy

The First Aid tree says what a concept is. A term says when she needs it. Folding them together would have been the obvious move and the wrong one: an exam that owned its concepts would fork her history, so material drilled for the Renal midterm would start from zero when it reappeared on the final. Exams therefore reference topics and concepts and never own them, and a parent topic pulls in its whole subtree.

SurfaceWhat it holdsDesign call
Terms & coursesHer filing systemDeleting a term detaches its courses rather than cascading - losing exam history to a mis-click is the worse failure
ExamsName, date, what it coversExam proximity was already in the priority formula, so adding an exam immediately changes what practice serves
VaultWhiteboard photos, questions, handoutsStorage works with no API key. Reading an image is opt-in, per image, never on upload
PinboardTopics, mnemonics, images she flagsNothing here is generated or scored. Everywhere else the engine decides; this is the one surface where she does
EmphasisWhat a professor stressedProposes a priority boost; she confirms it
Study planA day-by-day scheduleArithmetic computed, strategy generated - never the reverse

Emphasis proposes, she disposes

"Dr. Nassar said acid-base is heavily tested" is often better evidence than any textbook weighting, and the original spec asked for it. But a misheard remark that silently raised a concept's priority for a month would be very hard to notice and impossible to trace.

Resolution: a note is stored with who said it and how strongly, Claude proposes which concepts it points at, and the boost applies only when she confirms. It lives in concept.emphasis_boost, never folded into high_yield, so what her professor stressed stays separable from what the book says - and undoing it is exact rather than approximate. Source trust scales it: the same claim from an upperclassman counts half what it counts from the professor.

The whiteboard is evidence, not a photo

A brain dump is a retrieval attempt she has already performed. So when she asks the app to read one, the valuable half of the answer is not what she remembered - it is what a complete answer would contain that is absent. The analysis is told not to invent errors, and to say plainly when handwriting is illegible rather than guess: a confident misreading of her own notes is worse than an admission.

Plans that admit what they cannot do

# computed, never generated capacity = study_days x minutes_per_day / 1.0 min per question priority = weakness x exam_weight x forgettingRisk x (1.25 if never practised) questions = 6 if weak · 4 if developing · 3 · 2 · 1 if solid # two honesty rules, both enforced by tests - never schedules more minutes than she said she has - when capacity runs out, it NAMES what it dropped

A third warning fires in the opposite direction: when a plan uses less than half the time she set aside, it says so and explains that the shortfall is unmapped material rather than a scheduling error. Days are dealt round-robin so topics interleave, the weakest third gets a second pass at least two days later, and the final day is consolidation only.

Readiness is deliberately not a predicted score. There is no validation data behind this app, so a forecast would be invented precision. It reports weighted coverage, states how many mapped concepts have never been practised, and carries that caveat in its own payload so no screen can quietly drop it.

4Scope & drills

Telling the engine what it may serve, and four games aimed at the specific subtest pattern.

Scope

Practice drew from everything she had ever studied, so a finished Term 3 exam competed with the block she is actually sitting. Filtering by term, course or exam makes that a choice rather than an assumption.

Narrowing scope has a cost, and the UI says it

Everything outside the filter stops being served for review — it does not stop decaying. That is the correct trade the week before a midterm and the wrong one afterwards, so describe() returns the consequence as text and the panel prints it rather than hiding it.

Two smaller calls: a concept sitting on both a finished exam and an upcoming one is not previous material — the upcoming exam wins. And an impossible filter serves nothing and explains why, because silently ignoring the filter is the far more dangerous failure.

Drills, and what they honestly are

Four games built from concepts already in her bank, so all of it runs with no API key. Each one traces to a specific number in the report:

DrillComes fromDesign call
SequenceVisual span well above auditory spanSpan adapts to sit at your edge, not at a target
Chunk ItAWMI-R 78 — a bare list of seven is unusableNot graded for "correctness": many groupings are defensible, and marking one right teaches her to guess the app's answer
Odd One OutInhibition/Switching 10 — a strengthThe rule flips every round; this is the one that should feel good
Name ItNaming slow — retrieval is slow, not absentNever timed, near-misses accepted, cue on request

These do not fix a working-memory deficit

Evidence that working-memory training transfers to real capacity is weak. The app states that on the drills tab rather than burying it, because a study tool that implies it can raise her span would be selling her something.

What the drills do have support for: practising in the channel that works, rehearsing compensations she can apply in a real exam, and building content fluency. Extended time and a low-distraction room remain the interventions that actually help most — and those are accommodations, not exercises.

Drill results are written to their own table and never reach attempt. A drill is a skill exercise, not a knowledge test, and folding its scores into mastery would corrupt the model with a different task. Pace is compared only against her own earlier runs — the same rule that keeps rt_ms out of the mastery formula.

5Application, notes, pressure

It leaves the browser, it reads her notes, and it can put a clock on — carefully.

A real application

Start Menu and Desktop shortcuts launch it through pythonw.exe: no console, no browser tab, no URL. It takes a free port from the OS rather than fighting over one, and when packaged as an executable the database moves to %LOCALAPPDATA% — a frozen app's own folder is read-only and its extraction directory is temporary, which is the wrong place for the only copy of her study history. If no native webview is present it opens her browser and says so, rather than showing a blank window.

Critiquing notes

Measured offline, judged with Claude. The measurements — words per line, sentence length, longest unbroken list, whether a table exists at all — are arithmetic over her actual text, shown as numbers she can check. The critique quotes her own writing and rewrites one passage into the better shape, because a rewrite is usable and a principle is not.

Two claims this refuses to make

"Write by hand instead of typing." The laptop-versus-longhand finding is repeated everywhere and has not replicated cleanly. Telling her to change her whole workflow on a contested result would be passing off a preference as evidence.

"You're a visual learner." Learning styles have no support. The reason to route her visually is a measured ~1.5 SD gap between her own Symbol Span and her own auditory span — a fact about her, not a personality type. Both constraints are pinned by a test, not just by a prompt.

The framework is Dunlosky et al. (2013): practice testing and distributed practice rated high utility; elaborative interrogation, self-explanation and interleaving moderate; summarisation, highlighting and rereading low. Every flag names its basis, so "this list is longer than you can hold" and "rereading is low-utility" are visibly different kinds of claim. Quotes in the critique are verified against her text verbatim; an unverified one is marked in the UI rather than shown as fact.

A timer that never cuts her off

# presets off (default) · double time 180s · time and a half 135s · standard NBME 90s # behaviour past the limit bar turns amber · label reads "over the limit — keep going" nothing is graded · submit still offered · input still editable elapsed time is stored and never enters the mastery formula

She asked for exam pressure and this delivers it, but a hard cut-off would convert a formal accommodation into a stressor and defeat the purpose of practising at all. Going over is information. The clock counts up toward a limit rather than draining toward zero, for the same reason.

Reading the vignette

NBME stems are long on purpose and the question is at the bottom. The dissector splits a stem into the ask, lines that narrow it (who / when / numbers), background, and skim — on pattern matching alone, no API key — and flags negated stems loudly, since NOT/EXCEPT is the most common way to lose a question you knew.

Classification is deliberately conservative: an uncertain line is called background, never skim. Telling her to ignore a line that mattered is a far worse error than leaving one unclassified, so the heuristic is tuned to under-call padding. The reading strategy itself is standard test-taking advice, and the playbook labels it as such rather than dressing it up as a research finding — what is evidence-backed is the reason it helps her specifically: it reduces how much has to be held at once.

6Marking up the question

Per-question, not per-app: coloured marks over the actual phrases, and advice conditional on what is in that stem.

MarkWhat it meansWhy it earns a colour

The advice underneath is generated from the dissection, not chosen from a list. A stem with no numbers is told it is a pattern-recognition item; a stem with four is told to put them in a column. A lean stem is never lectured about padding it does not have, and a negated stem gets its warning before anything else.

Two regexes that could never match

A literal backspace character had been baked into the finding and history patterns, so both silently matched nothing and "Physical examination shows diaphoresis" was being marked as skim — advice to ignore the one line that carried the diagnosis. The patterns looked correct in the source; only repr() on the compiled pattern showed the .

Alongside it, 158/94 mm Hg was being marked as "94 mm" with the systolic left bare, and 37.0 C not marked at all. Compound patterns now come first, so a blood pressure is one value rather than a fragment.

The markup is checked by a test that reassembles the segments and compares them against the original line, so highlighting can never silently drop or duplicate her text — the failure mode that would be hardest to notice and worst to ship.

Note check moved

It was a top-level tab; it is now a collapsed section on Profile with three sources — paste, pick from the vault, or upload a document. Reading documents reuses the extractors the course-material pipeline already has, so a .docx of her notes is read the same way a .docx of a lecture is. A PDF with no text layer says it is probably a scan and points at the vault, rather than returning an empty review.

✓Audit & data safety

What was left after the plan: finding what was broken, and protecting the one thing that cannot be rebuilt.

Cold start

Every surface run against a completely empty database — the state a new user hits, and one that had never been tested end to end. All 26 GET endpoints returned 200, all 13 views rendered a real empty state, and the console stayed clean. Every destructive-path POST returned a usable message rather than a stack trace.

Three of those messages were leaking Python internals. str(KeyError("x")) is "'x'" — quotes included — so the UI was showing 'no such exam: nope'. The kind of thing that only turns up when you actually look.

Backups

The attempt table is the one thing here that cannot be regenerated. Questions can be rewritten, concepts re-extracted, mastery recomputed from history — but a year of answers is a year of answers, and it was sitting in a single SQLite file on one laptop with no way to get it out.

DecisionWhy
Automatic on every start, last 10 keptThe backup she remembers to take is the one she doesn't need
SQLite's .backup(), not a file copyCopying a database mid-write produces a file that looks fine and is corrupt
Restore snapshots the current data firstUndoing a restore has to be possible, or the button is a loaded gun
JSON export alongside the .dbA .db is only useful next to this app; her history should outlive it
Skipped if one was taken in the last 6 hoursA restart loop shouldn't churn through the ten slots

Building this surfaced a design smell worth fixing rather than routing around: backup.py was deriving the database path from app.DATA instead of asking db. Two sources for one fact is exactly how a backup ends up pointing at the wrong file, so db.path() is now the single answer and the test that caught it stayed.

08Phase plan

Your eight phases, with one reordering I'd argue for - and one phase inserted since.

Taxonomy moves from Phase 4 to Phase 1

Mastery tracking is meaningless without stable concept identity, and concept identity needs a topic tree to hang from. If Phase 1 ships session-scoped IDs, every attempt recorded in Phases 1–3 is orphaned when the taxonomy lands — the history you most want to keep is the history that gets thrown away. Seeding the taxonomy first costs a day; retrofitting it costs the data.
